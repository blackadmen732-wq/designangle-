The other half: light, dense, several things at once.

docs/app-patterns.html came from two dark media apps where one thing dominates the screen. Most of the work a small business actually does is the opposite case — a light ground, a person scanning, and five numbers that all matter. These are the patterns for that, and they are where the "make one thing huge and cut the rest" instruction stops being right.

Pattern 01

On a light ground, value alone stops separating things.

The dark pattern set says cards separate by value and need no border and no shadow: page #070707, card #1c1c1c. That works because dark has room underneath — you can go darker than the card and still have a surface.

White has nowhere to go. A card on white, separated only by value, is either invisible or dirty. So you get a hairline or a shadow instead, and the shadow is not one shadow.

Material 3 elevation is two shadows at every level: one tight and relatively dark, one wide and faint. Level 1 is 0 1px 2px / .30 plus 0 1px 3px 1px / .15. The tight one puts the edge down; the wide one gives it a room to sit in. A single soft shadow is the thing that reads as a template. 

/* Material 3, md-sys-elevation-shadow-1 and -2 */
--e1: 0 1px 2px 0 rgb(21 23 28 / .30), 0 1px 3px 1px rgb(21 23 28 / .15);
--e2: 0 1px 2px 0 rgb(21 23 28 / .30), 0 2px 6px 2px rgb(21 23 28 / .15);

Pattern 02

Sometimes five numbers are all the hero.

The design method says find the one thing and make it bigger than feels comfortable. On a media screen that is right: there is one artwork and one Play button. On an owner's morning screen it is wrong. Revenue, orders, average and refunds are all the reason the screen exists, and blowing one up to four times the others invents a priority nobody asked for.

The replacement rule: when several numbers are peers, make them identical and let the change carry the emphasis. Equal tiles read as a set. The one that moved is the one that gets a colour.

Tabular figures are not optional here. font-variant-numeric: tabular-nums makes digits the same width, so columns line up and a number changing does not shuffle the layout beside it.

Pattern 03

The dense row: a dot, two lines, one number.

Scanning is not reading. A person going down a list of thirty things is matching shapes, not sentences. The shape that works is always the same: a status mark on the left at a fixed column, the thing and its detail stacked in the middle, and the number right-aligned.

Two rules make it work. The middle column gets minmax(0,1fr) so long names wrap instead of pushing the number off the edge. And the detail line wraps rather than truncating — Front count… is not information.

Row height of 56px is the smallest that still clears the 44px touch target with its padding intact. Below that you are choosing density over being able to hit the row. 

.drow {
  display: grid;
  grid-template-columns: 8px minmax(0,1fr) auto;  /* 0 lets it wrap */
  min-height: 56px;  /* 44 target + padding */
}

Pattern 04

Status is a pair of colours, never one.

A status needs a background and a foreground chosen together, because the pair is what has to pass contrast. Picking a nice red and putting it on a light tint of itself is how you end up at 3.2:1 and never notice.

Four states is usually all there is: good, needs attention, wrong, and inactive. A fifth is almost always two of those wearing different hats.

Every pair below is checked with node tools/contrast.js check "<fg>" "<bg>", and the page is checked with node tools/audit.js. Never ship a tone pair you have not run through one of them — this is arithmetic, not judgement.

Pattern 05

One filled button survives the move to light.

This is the one rule from the dark set that does not bend. Two filled buttons means no primary action, on any ground. What changes is only that a filled button on white has to be dark enough to be obviously a button, so the ink colour does the work the accent did on dark.

Keep the visible height at whatever the design wants and grow the hit box with a pseudo-element. min-height: 44px here is the simple case; the shared template uses ::after where the look has to stay smaller.

Pattern 06

The bar sits on the edge. It does not float.

The dark set says navigation floats: a translucent blurred pill lifted off the bottom. That needs something to float above — artwork, a video, a dark field with depth in it.

On a white list there is nothing behind it. A floating pill over white reads as a thing that has come loose. Anchor it to the edge, give it a top hairline and the faintest upward shadow, and it reads as part of the furniture. 

.sticky-bar {
  border-top: 1px solid var(--line);
  box-shadow: 0 -1px 2px rgb(21 23 28 / .04);  /* barely there */
}

Pattern 07

The spacing scale three published systems agree on.

Dense screens live or die on spacing, because with this many elements the gaps are the only grouping you have. The scale below is the intersection of what Carbon, Material 3 and Uber Base Web all ship — not a preference.

2 · 4 · 8 · 12 · 16 · 24 · 32 · 40 · 48 · 64 appears in all three. Material builds from an explicit --md-sys-space-unit: 8px with quarter steps; Carbon and Uber both start their ladders at 2px. The 2 and the 4 are what a dense screen needs and what a marketing page never does.

What carried over from the dark set, unchanged. Hierarchy by value before size. Exactly one filled button. The brand colour spent once. Space groups things better than any border. Nothing frequent is animated.

What flipped. No glow — a light screen does not need lighting. Cards take a hairline or a two-part shadow, because value alone has nowhere to go. The bar is anchored, not floating. And several numbers are allowed to be equally important, which is the rule the dark set could not have found, because a media screen never has that problem.
